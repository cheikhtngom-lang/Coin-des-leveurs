Architecture des Données - "Coin des Éleveurs"

Ce document décrit l'architecture de la base de données (schéma relationnel) pour la plateforme SaaS.

Table des Matières

  • 1. Utilisateurs et Rôles
  • 2. Animaux et Annonces

  • 8. Relations et Cardinalités

1. Utilisateurs et Rôles

Table Users (Utilisateurs)

Gère tous les comptes de la plateforme.

  • id_user (PK) : Identifiant unique.
  • nom_complet : Nom et prénom de l'utilisateur.
  • email : Adresse email (Unique).
  • mot_de_passe : Mot de passe haché.
  • telephone : Numéro de téléphone.
  • role : Rôle (ENUM : 'Acheteur', 'Eleveur', 'Admin', 'Veterinaire').
  • date_inscription : Date de création du compte.
  • statut : État du compte (Actif, Suspendu, En attente).

Table Eleveur_Profils (Profils Éleveurs)

Données spécifiques aux éleveurs (Relation 1:1 avec Users).

  • id_profil (PK) : Identifiant unique.
  • id_user (FK) : Lien vers l'utilisateur.
  • nom_ferme : Nom de l'exploitation agricole.
  • region : Région d'élevage (ex: Thiès, Dakar).
  • description : Présentation de l'éleveur.
  • badge_verifie : Booléen (True si certifié).
  • abonnement_pro : Booléen (True si Premium).

2. Animaux et Annonces

Table Categories_Animaux

  • id_categorie (PK) : Identifiant.
  • nom_categorie : Nom (ex: Bovins, Ovins).

Table Annonces

  • id_annonce (PK) : Identifiant.
  • id_eleveur (FK) : Référence à l'éleveur.
  • id_categorie (FK) : Catégorie de l'animal.
  • titre : Titre de l'annonce.
  • race : Race spécifique (Gobra, Ladoum...).
  • poids_kg / age_mois : Mensurations.
  • prix : Prix de vente.
  • statut : Statut (Disponible, Vendu, Réservé).

3. Transactions et Commandes

Table Commandes

  • id_commande (PK) : Identifiant.
  • id_acheteur (FK) : Acheteur.
  • id_annonce (FK) : Animal acheté.
  • montant_total : Prix payé.
  • statut_paiement : (En attente, Payé, Échoué).
  • methode_paiement : (Wave, Orange Money, Carte).

4. Espace Communautaire (Forum)

Table Forum_Sujets (Topics)

  • id_sujet (PK) : Identifiant.
  • id_categorie (FK) : Catégorie du forum.
  • id_auteur (FK) : Éleveur (Auteur).
  • titre / contenu : Sujet de discussion.

Table Forum_Reponses (Messages)

  • id_reponse (PK) : Identifiant.
  • id_sujet (FK) : Sujet parent.
  • id_auteur (FK) : Auteur.
  • contenu : Texte.

5. Espace Foire Virtuelle (Live)

Table Foires (Événements)

  • id_foire (PK) : Identifiant.
  • id_eleveur (FK) : Organisateur.
  • titre : Titre de la foire.
  • date_prevue : Date du live.

Table Foire_Encheres (Offres)

  • id_enchere (PK) : Identifiant.
  • id_foire_animal (FK) : Animal concerné.
  • id_acheteur (FK) : Acheteur faisant l'offre.
  • montant_offre : Montant proposé.

6. Espace Administrateur & Support

Table Tickets_Support

  • id_ticket (PK) : Identifiant du ticket.
  • id_user (FK) : Auteur du ticket.
  • sujet : Sujet du problème.
  • message : Description détaillée.
  • statut : État (Ouvert, Résolu).

Table Transactions

  • id_transaction (PK) : Identifiant.
  • id_user (FK) : Utilisateur concerné.
  • type : (Abonnement, Commission, etc.).
  • montant : Montant financier.
  • date_transaction : Timestamp.

7. Espace Vétérinaire

Table Veterinaire_Profils

Données spécifiques aux vétérinaires (Relation 1:1 avec Users).

  • id_profil (PK) : Identifiant.
  • id_user (FK) : Lien vers l'utilisateur (Rôle: Veterinaire).
  • nom_cabinet : Clinique ou nom du cabinet.
  • geolocalisation : Coordonnées GPS / Adresse exacte.

8. Relations et Cardinalités

  • Un Utilisateur (Éleveur) peut publier plusieurs Annonces (1,n).
  • Un Utilisateur (Éleveur ou Acheteur) peut contacter un Vétérinaire via chat direct (1,n).
  • Une Annonce appartient à un seul Éleveur (1,1).
  • Un Acheteur peut passer plusieurs Commandes (0,n).
  • Une Foire est organisée par un seul Éleveur mais peut présenter plusieurs Animaux (1,n).
  • L'Administrateur gère tous les Tickets et Transactions (1,n).
